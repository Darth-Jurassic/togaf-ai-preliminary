# Preliminary 0014: Define Project Naming

- Record: Reusable policy
- Tags: preliminary, naming, identity

## Context

Inconsistent names weaken search, ownership and traceability. A reusable profile
must not choose an adopter's product, brand, domain, tenant or namespace.

## Decision

Discuss the naming model with the stakeholder before introducing concrete naming
rules. Record the selected display name, technical forms, allowed aliases,
ownership boundary and rename authority in an adopter-owned preliminary record.
Keep historical and external identifiers intact unless their owner authorizes a
rename; distinguish a prose naming decision from a code/API migration.

No company prefix, hostname, repository owner, package prefix or WSL distribution
is mandated by this reference profile.

## Consequences

Apply agreed naming consistently and migrate related filenames/companions/links
coherently. Do not rewrite source quotes, external references or another tenant's
identity to make them resemble the current project.
